# 테크니컬 SEO 이해하기

> 건물의 인테리어(콘텐츠)보다 먼저, 기초 공사(테크니컬 SEO)가 되어야 합니다.\
> — 아무리 좋은 글도, 구글 봇이 못 읽으면 0점.

---

## 0. 테크니컬 SEO란?

**검색엔진(구글 봇)이 내 사이트를 잘 읽고, 좋아할 수 있도록 기술적으로 최적화하는 것입니다.**

어렵게 느껴지시죠? 쉽게 비유해볼게요:

| 비유 | 콘텐츠 SEO | 테크니컬 SEO |
|------|----------|-------------|
| 건물 | 인테리어, 가구 (예쁜 벽지, 좋은 가구) | 기초 공사, 철근 구조 (튼튼한 뼈대) |
| 음식점 | 맛있는 요리 | 위생 등급, 주방 시설 |
| 자동차 | 외관 디자인 | 엔진 성능, 안전 등급 |
| 책 | 내용·문장 | 목차·색인·인쇄 품질 |

> 💡 **쉽게 말하면:**\
> 아무리 맛있는 식당이라도 **위생 등급이 D**면 손님이 안 오잖아요?\
> 구글도 마찬가지입니다.\
> 글이 아무리 좋아도 **기술 점수가 낮으면 상위 노출을 안 시켜줍니다.**

### 그래서 이걸 내가 해야 하나요?

**아닙니다!** 이게 이 강의의 핵심이에요.

보통 SEO 강의에서는 "콘텐츠 SEO"만 가르칩니다.\
테크니컬 SEO는? "그건 개발자한테 맡기세요~" 이러죠.\
왜? **어려우니까.**

하지만 이 강의에서는 **템플릿이 다 해결합니다.**\
여러분이 코드를 건드릴 일이 없어요.\
설치만 하면 테크니컬 SEO가 **자동으로** 적용됩니다.

## 1. 구글 봇 — 깊이 이해하기

"구글 봇"이라는 프로그램이 있습니다.\
정식 명칭은 **Googlebot**. 이 프로그램이 **전 세계 모든 웹사이트를 24시간 돌아다니면서 점수를 매깁니다.**

### 구글 봇이 일하는 3단계

```
1단계: 크롤링 (Crawling)
       ↓ 내 사이트에 방문 → HTML, CSS, JS, 이미지 다 읽음
2단계: 색인 (Indexing)
       ↓ 읽은 내용을 구글 거대한 DB에 저장
3단계: 랭킹 (Ranking)
       ↓ 누군가 검색하면 → DB에서 꺼내 순서 매김
```

이 3단계 어디서든 막히면 **검색 결과에 안 나옵니다.**

| 단계 | 문제 시 증상 | 해결책 |
|---|---|---|
| 크롤링 막힘 | 구글 봇이 사이트에 못 들어옴 | robots.txt 점검, 서버 응답 200 확인 |
| 색인 안 됨 | 구글 봇이 들어왔지만 저장 안 함 | 콘텐츠 품질, 중복 콘텐츠, noindex 태그 점검 |
| 랭킹 낮음 | 색인은 됐지만 검색 결과 뒤로 밀림 | 콘텐츠 SEO + 테크니컬 SEO 둘 다 |

### 크롤링 예산 (Crawl Budget)

구글 봇은 **모든 사이트에 무한정 머물지 않습니다.**\
사이트마다 "이 사이트에는 얼마나 시간을 쓸지" 예산이 정해져 있어요.

- **신생 사이트**: 예산 적음 → 하루 몇 페이지만 크롤링
- **권위 있는 사이트** (3년+ 운영, 글 많음): 예산 큼 → 새 글 올리면 몇 시간 안에 크롤링

> 💡 그래서 신생 사이트는 **사이트맵을 직접 제출**해서 "여기 새 글 있어요" 알려야 합니다.\
> 이건 9강~10강에서 다룹니다.

### 구글 봇이 보는 4가지

```
구글 봇이 내 사이트에 방문
    ↓
"이 사이트 빠른가?"          → Performance (성능)
"모든 사람이 쓸 수 있는가?"   → Accessibility (접근성)
"웹 표준을 지키는가?"         → Best Practices (모범 사례)
"검색엔진이 잘 읽는가?"       → SEO
    ↓
4가지 점수 합산 = Lighthouse Score (최대 400점)
    ↓
점수 높을수록 → 검색 결과 상위 노출!
```

> 💡 각각 100점 만점이에요. 합치면 **400점 만점**.\
> 이걸 측정하는 도구가 구글이 직접 만든 **Lighthouse**(라이트하우스)입니다.

## 2. Core Web Vitals — "사이트가 빠른가?"

구글이 **2021년부터 가장 중요하게 보는** 3가지 성능 지표입니다.\
공식 명칭: **Core Web Vitals**.

### 3가지 핵심 지표

| 지표 | 쉬운 뜻 | 비유 | 합격 기준 | 측정 방법 |
|------|---------|------|----------|----------|
| **LCP** (Largest Contentful Paint) | 화면이 뜨는 데 걸리는 시간 | 문 열었는데 불이 언제 켜지냐 | 2.5초 이하 | 가장 큰 요소가 나타날 때까지의 시간 |
| **INP** (Interaction to Next Paint) | 버튼을 눌렀을 때 반응 속도 | 버튼 눌렀는데 언제 반응하냐 | 0.2초 이하 | 2024년 3월부터 FID 대체 |
| **CLS** (Cumulative Layout Shift) | 화면이 갑자기 움직이는 정도 | 글 읽는데 광고가 끼어들어 화면이 밀리는 거 | 0.1 이하 | 누적된 레이아웃 이동 점수 |

:::warning CLS가 가장 흔한 감점 원인
글을 읽고 있는데 갑자기 광고가 뜨면서 화면이 밀리는 거 겪어보셨죠?\
그게 CLS입니다. 다음 케이스에서 잘 발생해요:

- 이미지에 width/height 속성이 없을 때
- 광고가 비동기로 로드될 때
- 웹폰트가 늦게 로드돼서 글자 크기가 갑자기 바뀔 때
- 동적으로 추가되는 배너·팝업

→ 걱정 마세요! **우리 템플릿은 이걸 자동으로 잡아줍니다.**
:::

### Lab 데이터 vs Field 데이터

이건 좀 깊은 얘기지만 알아두면 좋아요.

| 종류 | 정의 | 도구 |
|---|---|---|
| **Lab 데이터** | 통제된 환경에서 측정 (내 컴퓨터에서 한 번 측정) | Chrome DevTools Lighthouse |
| **Field 데이터** | 실제 사용자들이 경험한 데이터 | Chrome User Experience Report (CrUX), PageSpeed Insights |

> 구글은 **Field 데이터**를 진짜 검색 순위에 반영합니다.\
> Lab 데이터에서 100점이어도, 실제 사용자가 느린 환경에서 느리게 느꼈으면 감점됩니다.

## 3. 모바일 우선 색인 (Mobile-First Indexing)

2019년부터 구글은 **모바일 버전을 기준으로** 사이트 점수를 매깁니다.\
PC 버전이 아무리 좋아도, 모바일이 별로면 점수 다 깎입니다.

### 왜 모바일이 우선인가?

- 전 세계 검색의 **60% 이상이 모바일**에서 발생
- 한국은 모바일 비중이 더 높음 (70%+)
- 모바일에서 안 보이거나 느린 사이트는 사용자가 바로 나가버림

### 모바일 친화의 조건

| 항목 | 좋은 예 | 나쁜 예 |
|---|---|---|
| **반응형 디자인** | 화면 크기에 맞춰 자동 조정 | PC 디자인 그대로 → 작아서 안 보임 |
| **글자 크기** | 최소 16px | 12px (모바일에서 너무 작음) |
| **터치 영역** | 버튼 48×48px 이상 | 너무 작아서 손가락으로 못 누름 |
| **가로 스크롤** | 없음 (세로만) | 가로로 밀어야 보임 |
| **팝업** | 작거나 없음 | 화면 전체 가리는 광고 |

> 💡 **우리 템플릿은 100% 반응형**입니다. 모든 항목 통과.

## 4. 시맨틱 HTML — "사이트 구조가 정리되어 있는가?"

"시맨틱(Semantic)"이란 "의미가 있는"이라는 뜻입니다.\
시맨틱 HTML이란, 구글 봇한테\
**"여기가 제목이야, 여기가 본문이야, 여기가 하단이야"**\
알려주는 구조입니다.

### 시맨틱 vs 비시맨틱

```html
<!-- ❌ 나쁜 예: 그냥 div만 잔뜩 -->
<div class="top">
  <div class="big-text">제목</div>
</div>
<div class="content">
  <div>본문...</div>
</div>
<div class="bottom">
  <div>저작권...</div>
</div>

<!-- ✅ 좋은 예: 시맨틱 태그 사용 -->
<header>
  <h1>제목</h1>
</header>
<main>
  <article>본문...</article>
</main>
<footer>
  <p>저작권...</p>
</footer>
```

쉽게 비유하면:

- **나쁜 구조** = 서류가 바닥에 아무렇게나 흩어져 있는 사무실\
  → 구글 봇: "이게 뭔지 모르겠는데..."
- **좋은 구조** = 서류가 폴더별로 깔끔하게 정리된 사무실\
  → 구글 봇: "오, 깔끔하다! 이 사이트 좋은데?"

### 헤딩 구조 (H1, H2, H3)

- **H1**: 페이지당 **딱 1개** (페이지 제목)
- **H2**: 큰 섹션 제목
- **H3**: 하위 섹션
- **H4~H6**: 더 깊은 하위

```
H1: 맥북 에어 M3 발열 해결법
  ├─ H2: 발열 원인 4가지
  │   ├─ H3: 고사양 작업
  │   └─ H3: 환경 요인
  └─ H2: 해결 방법 3가지
      ├─ H3: 소프트웨어 설정
      └─ H3: 하드웨어 관리
```

구글 봇은 이 구조를 보고 **"이 페이지가 뭘 다루는 글인지"** 파악합니다.

> 💡 여러분이 이 구조를 직접 만들 필요 없습니다.\
> **마크다운으로 글을 쓰면 자동으로 변환**됩니다. (`# = H1, ## = H2, ### = H3`)

## 5. 메타 태그 — "이 사이트가 뭔지 알려주는 명함"

구글에서 뭔가를 검색하면, 각 결과에 **제목**과 **설명**이 보이잖아요?\
그게 메타 태그입니다.

### 검색 결과에 보이는 4가지

```
┌─────────────────────────────────────────────┐
│ 🌐 myblog.com › posts › macbook-heat        │ ← URL
│                                             │
│ 맥북 에어 M3 발열 해결법 — 실제 사례 5가지   │ ← Title (메타)
│                                             │
│ 맥북 에어 M3에서 발열이 심하다면? 30분만에   │ ← Description (메타)
│ 해결하는 방법을 정리했습니다. 실제 측정 결과 │
│ 와 함께...                                  │
│                                             │
│ [썸네일 이미지]                              │ ← OG Image
└─────────────────────────────────────────────┘
```

이게 잘 되어 있으면 **클릭률이 3%에서 15%까지** 올라갑니다.\
같은 순위라도 설명이 매력적이면 더 많이 클릭하는 거죠.

### 필수 메타 태그

| 태그 | 역할 | 권장 길이 |
|---|---|---|
| `<title>` | 검색 결과의 파란 제목 | 50~60자 |
| `<meta description>` | 제목 아래 설명 글 | 150~160자 |
| `<meta og:image>` | SNS 공유 시 썸네일 (Facebook, 카톡 등) | 1200×630px |
| `<link rel="canonical">` | "이 페이지의 원본은 여기다" 알려주기 (중복 방지) | URL |

> 💡 **우리 템플릿은 메타 태그를 자동으로 만들어줍니다.**\
> 글 제목을 쓰면 자동으로 검색 결과용 제목과 설명이 생성됩니다.

## 6. 구조화 데이터 (Schema.org) — "검색 결과를 풍부하게"

구조화 데이터는 구글 봇에게 **"이 페이지는 어떤 타입의 콘텐츠야"** 알려주는 코드입니다.

### 예시: 블로그 글에 적용하면

```
일반 검색 결과:
─────────────
맥북 에어 M3 발열 해결법
설명 텍스트...

구조화 데이터 적용 검색 결과:
─────────────
[썸네일] 맥북 에어 M3 발열 해결법
        ⭐⭐⭐⭐⭐ 4.8 (124 리뷰)
        📅 2024-05-01 · 👤 김지원
        설명 텍스트...
```

별점, 작성자, 날짜, 썸네일이 같이 표시 → **클릭률 2~3배 상승**.

### 자주 쓰이는 타입

| 타입 | 용도 |
|---|---|
| Article | 일반 글 |
| BlogPosting | 블로그 글 |
| HowTo | 단계별 가이드 |
| FAQPage | FAQ 페이지 |
| Recipe | 요리 레시피 |
| Product | 제품 페이지 |
| Review | 리뷰 |

> 💡 **우리 템플릿은 BlogPosting + Article 자동 생성.**\
> 글 발행하면 구조화 데이터가 자동으로 포함됩니다.

## 7. 사이트맵 & robots.txt — "구글에 지도 제출"

| 파일 | 쉽게 말하면 | 비유 |
|------|-----------|------|
| **sitemap.xml** | 내 사이트에 어떤 글들이 있는지 목록 | 건물 도면을 시청에 제출 |
| **robots.txt** | 구글 봇한테 "어디는 봐도 되고 어디는 안 돼" 알려주는 안내문 | 건물 출입 허용 안내 |

### sitemap.xml 예시
```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset>
  <url>
    <loc>https://myblog.com/posts/macbook-heat</loc>
    <lastmod>2024-05-01</lastmod>
    <priority>0.8</priority>
  </url>
  <url>
    <loc>https://myblog.com/posts/macbook-keyboard</loc>
    <lastmod>2024-05-03</lastmod>
    <priority>0.8</priority>
  </url>
</urlset>
```

구글 봇은 이걸 보고 "오, 이 사이트엔 이런 글이 있구나" 파악합니다.

### robots.txt 예시
```
User-agent: *
Allow: /
Disallow: /admin/
Sitemap: https://myblog.com/sitemap.xml
```

> 💡 이것도 **우리 템플릿에 다 포함**되어 있습니다.\
> 글을 추가할 때마다 사이트맵이 자동으로 업데이트됩니다.

## 8. 내부 링크 (Internal Linking) — 가장 저평가된 SEO

블로그 글 안에서 **다른 글로 연결**하는 링크입니다.

### 왜 중요한가?

1. **구글 봇이 사이트를 더 깊이 탐색**합니다
   - 한 페이지 → 5개 다른 페이지로 연결 → 구글 봇 머무는 시간 ↑
2. **권위(Authority)가 글들 사이로 흐릅니다**
   - 1위 글에서 신규 글로 링크 → 신규 글이 빠르게 상위 진입
3. **사용자가 더 오래 머뭅니다**
   - 체류 시간 증가 → 구글이 "이 사이트 유용하구나" 판단

### 좋은 내부 링크 vs 나쁜 내부 링크

```
❌ 나쁜 예:
"여기 클릭하세요"
"자세히 보기"

✅ 좋은 예:
"맥북 에어 M3 발열 원인 5가지"  ← 키워드가 링크 텍스트
"애드센스 신청 방법은 별도 글에서 다뤘습니다"
```

링크 텍스트(앵커 텍스트)에 **키워드가 들어가야** 검색엔진이 인식합니다.

## 9. 페이지 경험 시그널 (Page Experience Signals)

구글이 2021년에 도입한 종합 지표입니다.\
**Core Web Vitals + 다음 항목들**을 합쳐서 평가합니다.

| 시그널 | 합격 기준 |
|---|---|
| Core Web Vitals (LCP, INP, CLS) | 위 섹션 참조 |
| HTTPS | 보안 연결 사용 (`https://`) |
| 모바일 친화성 | 모바일에서 정상 표시 |
| 침입적 광고 없음 | 화면 가리는 팝업 X |
| 안전한 브라우징 | 멀웨어·피싱 없음 |

> 💡 **우리 템플릿은 5가지 전부 자동 통과**합니다.\
> Vercel HTTPS는 무료 자동, 침입 광고 없음, 멀웨어 없음.

## 10. 테크니컬 SEO vs 콘텐츠 SEO — 정리

| | 테크니컬 SEO | 콘텐츠 SEO |
|---|---|---|
| **비유** | 건물의 기초/구조 | 건물의 인테리어/입주민 |
| **작업** | 사이트 속도, 구조, 접근성 | 키워드 선정, 글쓰기 |
| **빈도** | 처음 한 번 세팅하면 끝 ✅ | 지속적으로 글 작성 |
| **누가 하나?** | **템플릿이 자동으로!** ✅ | 여러분이 하는 것 |
| **효과** | 기반 점수 (1.5배~3배 부스트) | 트래픽 직접 유입 |
| **잘못되면** | 어떤 글을 써도 노출 X | 좋은 사이트인데 글이 없음 |

> 🎯 **이 강의의 핵심:**\
> 테크니컬 SEO는 **템플릿**이 다 해결합니다.\
> 여러분은 **콘텐츠(글)**에만 집중하면 됩니다.

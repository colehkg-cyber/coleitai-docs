# SEO 기초 — 구글이 직접 알려주는 원리

> 본 문서는 [Google Search Central 공식 SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide?hl=ko)를 기반으로 작성되었습니다.\
> 추측이나 카더라가 아닌, **구글이 직접 발표한 공식 가이드라인**을 따릅니다.

---

## 1. SEO란 뭔가요?

### 한 줄 정의

> **검색엔진이 내 콘텐츠를 잘 이해하도록 돕고, 사람들이 내 사이트를 방문할지 결정하도록 돕는 모든 작업.**

### 구글의 공식 입장

구글이 직접 명시한 두 가지 진실:

| 진실 | 의미 |
|---|---|
| **1위를 보장하는 비결은 없다** | "이것만 하면 1위" 같은 마법은 없음 |
| **원칙을 따르면 노출 가능성이 높아진다** | 정공법을 꾸준히 → 결과가 나옴 |

### 검색 결과 반영 시간

> 변경사항이 검색결과에 반영되기까지 **몇 주~몇 달**이 걸릴 수 있습니다.

조급해하지 마세요. SEO는 **장기 게임**입니다.

| 작업 | 반영 시간 |
|---|---|
| 새 글 발행 → 색인 | 며칠 ~ 2주 |
| 색인 → 검색 결과 등장 | 1주 ~ 1개월 |
| 신생 사이트 → 안정적 순위 | 3~6개월 |
| 권위 사이트 → 1페이지 진입 | 6개월~1년 |

---

## 2. 구글은 어떻게 작동하나요? — 3단계

구글이 검색 결과를 만드는 과정은 정확히 **3단계**입니다.\
이 흐름을 이해해야 SEO 전략이 보입니다.

```
┌─────────────┐    ┌─────────────┐    ┌──────────────┐
│ ① 크롤링    │ →  │ ② 색인 생성  │ →  │ ③ 검색결과    │
│   (탐색)    │    │   (저장)    │    │   게재(순위)  │
└─────────────┘    └─────────────┘    └──────────────┘
```

### ① 크롤링 (Crawling) — 탐색

구글이 **Googlebot**이라는 로봇을 보내서 인터넷을 돌아다니며 페이지를 수집합니다.

#### 구글이 내 페이지를 발견하는 방법

1. **다른 사이트에서 내 페이지로 연결된 링크** (외부 링크/백링크)
2. **내가 직접 제출한 사이트맵** (`sitemap.xml`)
3. **Google Search Console로 직접 URL 제출** (수동)

> 💡 신생 사이트는 다른 사이트의 링크가 없으니 **사이트맵 제출이 필수**입니다.\
> 우리 템플릿은 `sitemap.xml`을 자동 생성합니다.

#### 크롤링이 막히는 이유

| 원인 | 해결 |
|---|---|
| 서버 오류 (5xx 응답) | 서버 안정성 점검 (Vercel은 거의 문제 없음) |
| `robots.txt`에서 차단 | 차단 규칙 점검 |
| 로그인 필요한 페이지 | 로그인 없이 접근 가능하게 |
| 크롤 예산 부족 | 사이트 권위 ↑ + 사이트맵 정기 업데이트 |

---

### ② 색인 생성 (Indexing) — 저장

크롤링한 페이지를 분석해서 구글 데이터베이스에 저장합니다.

#### 분석 대상

- 페이지 제목 (`<title>` 태그)
- 본문 내용
- 이미지의 alt 텍스트
- 페이지 내 링크
- 구조화 데이터 (Schema.org)
- 헤딩 구조 (H1, H2, H3)
- 발행 날짜 / 수정 날짜

> 색인 = 구글의 거대한 도서관에 내 글이 꽂히는 것

#### 색인이 안 되는 이유

| 원인 | 해결 |
|---|---|
| 콘텐츠 품질이 낮음 | 깊이 있고 고유한 글 작성 |
| `noindex` 메타 태그 | 태그 제거 |
| 자바스크립트로만 렌더링 | SSG/SSR로 HTML 렌더링 (Next.js 자동) |
| 중복 콘텐츠 | canonical 태그 설정 (자동) |
| 너무 얇은 콘텐츠 | 최소 500자 이상, 충분한 깊이 |

> 💡 우리 템플릿은 Next.js SSG 사용 → 자바스크립트 렌더링 문제 없음.

---

### ③ 검색결과 게재 (Serving) — 순위

사용자가 검색하면 저장된 페이지 중 **가장 관련성 높은 것**을 보여줍니다.

#### 순위 결정 요소

- 사용자의 **위치** (한국에서 검색 vs 미국에서 검색)
- 사용자의 **언어** (한국어 vs 영어)
- 사용자의 **기기** (모바일 vs PC)
- 검색어와 콘텐츠의 **관련성**
- 콘텐츠의 **품질** (E-E-A-T)
- 페이지 **사용자 경험** (Core Web Vitals)
- 사이트의 **권위** (백링크 등)

#### 구글의 약속

> **구글은 돈을 받고 순위를 높여주지 않는다.**\
> 순위는 알고리즘으로만 결정된다. — Google Search Central

광고(Sponsored, Ads)와 검색 결과는 완전히 별개입니다.

#### 색인은 됐는데 안 보이는 이유

| 원인 | 해결 |
|---|---|
| 검색어와 콘텐츠가 관련 없음 | 키워드 의도에 맞게 작성 |
| 콘텐츠 품질이 낮음 | E-E-A-T 강화 |
| 경쟁 글이 더 좋음 | 차별화된 정보 추가 |
| 사이트 권위가 낮음 | 시간 + 글 누적 + 백링크 |

## 3. 구글이 원하는 콘텐츠 — E-E-A-T

구글의 순위 시스템이 **공식적으로 우선순위를 두는 기준**입니다.\
2022년 12월부터 기존 E-A-T에 Experience를 추가하여 E-E-A-T가 되었습니다.

### 4가지 기준

| 약자 | 풀네임 | 한국어 | 블로그에서 예시 |
|---|---|---|---|
| **E** | **E**xperience | 경험 | 내가 직접 써본 제품 리뷰 |
| **E** | **E**xpertise | 전문성 | 해당 분야를 잘 아는 사람이 쓴 글 |
| **A** | **A**uthoritativeness | 권위 | 다른 사이트들이 내 글을 링크함 |
| **T** | **T**rustworthiness | 신뢰 | 정확한 정보, 출처 명시 |

### 가장 중요한 것: 신뢰 (Trust)

> 가장 중요한 건 **신뢰(Trust)**.\
> 나머지 3개(경험·전문성·권위)는 신뢰를 쌓기 위한 요소들. — Google Search Central

```
        T (신뢰)
        ▲
        │
   ┌────┼────┐
   │    │    │
   E    E    A
 (경험) (전문) (권위)
```

### 분야별 E-E-A-T 가중치

콘텐츠 분야에 따라 어떤 요소가 더 중요한지 다릅니다.

| 분야 | 가장 중요한 요소 | 이유 |
|---|---|---|
| **YMYL** (Your Money Your Life) — 의료·금융·법률 | 전문성 + 신뢰 | 잘못된 정보가 사용자에게 큰 피해 |
| **리뷰·평가** | 경험 | 직접 써본 사람이 쓴 글이 가치 있음 |
| **취미·DIY** | 경험 + 전문성 | 실제로 해본 사람의 노하우 |
| **뉴스·시사** | 권위 + 신뢰 | 출처가 명확한 보도 |
| **일반 정보** | 전문성 + 신뢰 | 정확하고 깊이 있는 정보 |

> 💡 본인이 가장 강점을 가진 분야를 골라야 E-E-A-T가 자연스럽게 강해집니다.

### E-E-A-T를 강화하는 실천 방법

| 항목 | 실천 방법 |
|---|---|
| **Experience** | "제가 한 달간 직접 써본 결과...", "실제 측정값 첨부..." 같은 1인칭 경험 |
| **Expertise** | 작성자 프로필 페이지 추가, 자격증·경력 명시 |
| **Authority** | 출처가 좋은 외부 사이트 인용, 외부 사이트가 내 글을 인용하게 만들기 |
| **Trust** | 출처 링크, HTTPS, 회사·저자 정보, 정확한 사실 |

## 4. 좋은 콘텐츠 vs 나쁜 콘텐츠

구글이 명시한 **공식 평가 기준**입니다.

### ✅ 구글이 보상하는 콘텐츠 (사람을 위한 콘텐츠)

| 항목 | 체크 포인트 |
|---|---|
| **고유성** | 직접 경험하거나 조사한 고유한 정보가 있다 |
| **만족도** | 독자가 읽고 나서 목적을 달성했다고 느낀다 |
| **공유 가치** | 북마크하거나 친구에게 공유하고 싶다 |
| **저자 명확성** | 저자가 누구인지 명확하다 |
| **깊이** | 표면적이 아닌, 깊이 있는 정보 |
| **정확성** | 사실관계가 정확하고, 출처가 명시됨 |
| **최신성** | 시의성 있는 정보는 최신 상태 유지 |

### ❌ 구글이 패널티를 주는 콘텐츠 (검색엔진을 위한 콘텐츠)

| 패턴 | 문제 |
|---|---|
| **검색 트래픽 유도만 목적** | 사용자 가치는 0, 키워드만 가득 |
| **여러 주제를 대량으로 얕게** | 한 사이트가 모든 주제를 얕게 다룸 |
| **다른 사이트 내용 요약** | 원본 사이트가 더 가치 있음 |
| **날짜만 바꾸고 내용은 그대로** | 신선도 조작 |
| **AI로만 뚝딱 만들고 검수 없음** | 검증되지 않은 정보 양산 |
| **얇은 콘텐츠 (Thin content)** | 200~500자, 깊이 없음 |
| **키워드 스터핑** | 키워드를 부자연스럽게 반복 |
| **클릭베이트** | 제목과 내용이 다름 |

### 구글의 AI 콘텐츠에 대한 공식 입장

> AI로 초안을 쓰되, **반드시 내 경험과 판단을 더해야 한다.**\
> AI 생성 사실을 숨기면 신뢰도가 떨어진다.

#### AI 글쓰기 가이드라인

1. ✅ AI로 초안 생성 → OK
2. ✅ 사람이 검수·수정·경험 추가 → 필수
3. ✅ AI 사용 사실을 적절히 공개 → 권장 (의료·금융은 필수)
4. ❌ AI 양산 + 검증 없음 → 패널티

## 5. 콘텐츠 자가 진단 — 3가지 질문

구글이 글 발행 전 자기 검열용으로 제시한 **공식 자가 진단**입니다.

### Q1. 누가 만들었나? (Who)

체크 사항:
- [ ] 저자 정보가 명확한가?
- [ ] 바이오(소개글)가 있는가?
- [ ] 작성자의 전문성/경험을 확인할 수 있는가?
- [ ] 연락처가 있는가?

> 💡 우리 템플릿은 작성자 정보 자동 표시 + 저자 페이지 생성.

### Q2. 어떻게 만들었나? (How)

체크 사항:
- [ ] 직접 테스트했나?
- [ ] AI를 썼다면 어떻게 활용했는지 밝혔나?
- [ ] 1차 자료를 사용했나, 다른 사이트 요약인가?
- [ ] 사실 확인 과정이 있었나?

### Q3. 왜 만들었나? (Why)

체크 사항:
- [ ] 사람을 돕기 위해서인가?
- [ ] 단순히 검색 순위를 위해서인가?
- [ ] 광고/제휴 수익만이 목적인가?

> 💡 **사람을 돕는 게 1순위, 수익은 부산물**이 되어야 합니다.\
> 이게 구글이 보상하는 사이트의 핵심 마인드셋.

## 6. URL 구조와 사이트 구성

### URL 작성 원칙

#### ✅ 좋은 URL

```
https://myblog.com/review/macbook-air-m3
https://myblog.com/finance/etf-beginner-guide
https://myblog.com/tech/how-to-fix-macbook-heat
```

- 의미 있는 영문 단어 포함
- 하이픈(-)으로 단어 구분
- 짧고 명확

#### ❌ 나쁜 URL

```
https://myblog.com/2/6772656D70793443617402
https://myblog.com/?p=1234
https://myblog.com/카테고리1/post-id-2024-05-01-3
```

- 숫자/암호 같은 문자
- 한글 (인코딩되어 깨짐)
- 동적 매개변수
- 너무 김

### 폴더(카테고리) 구조

비슷한 주제끼리 묶기:

```
/tech/
  macbook-review
  ipad-vs-macbook
  iphone-15-pro-review

/finance/
  etf-beginner
  isa-account-guide
  tax-saving-tips

/travel/
  jeju-3-day-itinerary
  europe-backpacking
  budget-travel-tips
```

### 사이트 구조의 효과

1. **사용자 친화** — "이 카테고리에 비슷한 글 더 있구나"
2. **구글 봇 친화** — "이 사이트는 tech, finance, travel 주제구나"
3. **권위 집중** — 같은 카테고리 글들이 서로 권위를 강화

## 7. 스니펫(Snippet) — 검색결과에 보이는 설명글

구글 검색결과에서 제목 아래에 나오는 짧은 설명 텍스트입니다.

```
┌──────────────────────────────────────────────┐
│ myblog.com › review › macbook-air-m3         │
│                                              │
│ 맥북 에어 M3 리뷰 — 디자인부터 배터리까지     │ ← 제목
│                                              │
│ 2개월간 직접 사용해본 맥북 에어 M3의 솔직한    │ ← 스니펫
│ 리뷰입니다. 배터리 15시간, 발열 없음, 단점은  │
│ 포트 2개...                                  │
└──────────────────────────────────────────────┘
```

### 스니펫을 결정하는 것

구글이 자동으로 생성하지만, **메타 디스크립션 태그**가 잘 쓰여 있으면 그걸 우선 사용합니다.

```html
<meta name="description"
      content="2개월간 직접 사용해본 맥북 에어 M3 솔직 리뷰.
              배터리, 발열, 성능, 가격 대비 만족도까지 전부 공개합니다." />
```

### 메타 디스크립션 작성 규칙 (구글 공식)

| 규칙 | 내용 |
|---|---|
| **길이** | 155자 이내 (더 길면 잘림) |
| **고유성** | 모든 글마다 다르게 작성 |
| **내용** | 페이지 핵심 내용 요약 |
| **클릭 유도** | 매력적이지만 과장 X |
| **금지** | 키워드만 나열 금지 |

#### ❌ 나쁜 예
```
맥북, 애플, 리뷰, M3, 노트북, 성능, 가격
```
키워드만 나열 → 사람이 읽기 싫음 → 클릭률 ↓

#### ✅ 좋은 예
```
2개월간 직접 써본 맥북 에어 M3 솔직 리뷰. 배터리 15시간 실사용 결과와
포트 2개의 불편함, 학생/직장인 추천 여부까지 정리했습니다.
```
문장이 자연스러움 + 구체적 수치 + 누구를 위한 글인지 명시

> 💡 우리 템플릿은 글 작성 시 메타 디스크립션을 자동 생성합니다.\
> AI에게 "메타 디스크립션 155자 이내로 매력적으로" 요청 가능.

## 8. 추천 스니펫 (Featured Snippet) — 구글 검색 0위

일반 검색결과보다 **위에** 표시되는 특별 박스입니다.\
클릭률이 평균보다 **2~3배** 높습니다.

```
┌─────────────────────────────────────────┐
│ 삶은 달걀 만드는 방법                    │
│                                         │
│ 1. 냄비에 물을 붓는다                   │
│ 2. 달걀을 넣고 끓인다                   │
│ 3. 7~10분 후 꺼낸다                     │
│                                         │
│                   ↗ myblog.com           │
└─────────────────────────────────────────┘
```

### 추천 스니펫의 4가지 형식

| 형식 | 모습 | 적합한 콘텐츠 |
|---|---|---|
| **단락(Paragraph)** | 40~50자 정의 텍스트 | "XXX란?" 질문 |
| **목록(List)** | 순서/비순서 리스트 | "XXX 방법", "XXX 종류" |
| **표(Table)** | 비교표 | "XXX vs YYY", "XXX 가격" |
| **동영상** | YouTube 영상 | 튜토리얼 |

### 추천 스니펫에 선정되려면

구글이 자동으로 선정합니다. 직접 지정할 수 없습니다.\
하지만 **가능성을 높이는 방법**은 있습니다:

#### 전략 1: 질문형 H2 + 짧은 답변

```markdown
## 맥북 에어 M3 발열은 정상인가요?

맥북 에어 M3의 70~85도는 정상 범위입니다.
다만 85도 이상이 30분 이상 지속되면 발열 관리가 필요합니다.

(이어지는 상세 설명...)
```

#### 전략 2: 단계별 정리

```markdown
## 맥북 에어 M3 발열 줄이는 방법

1. 활성 상태 보기에서 CPU 사용률 높은 앱 종료
2. 노트북 받침대 사용으로 통풍 확보
3. 시스템 환경설정에서 배터리 모드 변경
```

#### 전략 3: 표로 정리

```markdown
## 맥북 에어 vs 맥북 프로 차이

| 항목 | 에어 | 프로 |
|---|---|---|
| 가격 | ₩1,690,000 | ₩2,790,000 |
| 무게 | 1.24kg | 1.55kg |
| 배터리 | 18시간 | 22시간 |
```

### 추천 스니펫 노리는 글의 공통점

- H2/H3 제목을 **질문 형태**로 작성 ("XXX 방법", "XXX란?")
- 답변을 **간결하고 명확하게** 정리 (목록, 표, 단계별)
- 제목 바로 다음에 **핵심 답변**부터 배치 (역피라미드)
- **FAQ 섹션** 추가
- **구조화 데이터** (Schema.org FAQPage, HowTo) 적용

> 💡 우리 템플릿은 FAQ/HowTo 구조화 데이터를 자동 적용합니다.

## 9. 사이트맵 (Sitemap) — 구글에 제출하는 지도

### sitemap.xml이란?

내 사이트에 어떤 페이지들이 있는지 **목록을 XML 파일로** 만들어 구글에 제출하는 것.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://myblog.com/review/macbook-air-m3</loc>
    <lastmod>2024-05-01</lastmod>
    <priority>0.8</priority>
  </url>
  <url>
    <loc>https://myblog.com/finance/etf-beginner</loc>
    <lastmod>2024-05-03</lastmod>
    <priority>0.8</priority>
  </url>
</urlset>
```

### 왜 필요한가?

- 신생 사이트는 **백링크가 거의 없음** → 구글이 발견 못 함
- 사이트맵을 제출하면 구글 봇이 "여기 글이 있구나" 빠르게 인식
- 새 글을 올릴 때마다 자동으로 사이트맵 업데이트 → 빠른 색인

### Google Search Console에 제출하기

1. https://search.google.com/search-console 접속
2. 사이트 등록 (도메인 또는 URL 접두어)
3. 왼쪽 메뉴 **사이트맵** 클릭
4. `sitemap.xml` 입력 → 제출

> 💡 우리 템플릿은 sitemap.xml을 자동 생성합니다.\
> 글을 발행할 때마다 자동 갱신.

## 10. robots.txt — 구글 봇에게 안내문

### robots.txt란?

구글 봇한테 "어디는 봐도 되고, 어디는 보지 마" 알려주는 텍스트 파일.

```
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /api/
Sitemap: https://myblog.com/sitemap.xml
```

| 명령 | 의미 |
|---|---|
| `User-agent: *` | 모든 검색엔진 봇에게 적용 |
| `Allow: /` | 사이트 전체 크롤 허용 |
| `Disallow: /admin/` | `/admin/` 경로는 크롤 금지 |
| `Sitemap: ...` | 사이트맵 위치 알려주기 |

### 자주 하는 실수

❌ **실수 1**: 전체 사이트 차단

```
User-agent: *
Disallow: /
```

→ 구글이 사이트 전체를 크롤 못 함 → 검색 결과에서 사라짐!

❌ **실수 2**: 사이트맵 누락

→ 신생 사이트는 색인이 늦어짐

> 💡 우리 템플릿은 robots.txt를 올바르게 자동 생성합니다.\
> 관리자 페이지(`/admin/`)는 차단, 사이트맵 명시.

## 11. 실전 체크리스트 — 글 발행 전 확인

글을 발행하기 전에 이 체크리스트를 돌리세요.

### 기본 SEO

- [ ] 제목(H1)에 핵심 키워드 포함
- [ ] 메타 디스크립션 155자 이내로 작성
- [ ] URL에 의미 있는 키워드 포함 (영문 권장)
- [ ] 이미지에 alt 텍스트 작성
- [ ] H1은 페이지당 1개만
- [ ] H2 → H3 순서로 헤딩 계층 준수

### 콘텐츠 품질 (E-E-A-T)

- [ ] **이 글에만 있는 정보**가 1개 이상 있는가?
- [ ] 저자(나)의 **직접 경험이나 의견**이 포함되었는가?
- [ ] 독자가 글을 다 읽고 **원하는 답을 얻을 수 있는가**?
- [ ] 제목이 내용과 **일치**하는가? (낚시성 제목 금지)
- [ ] **사실관계**가 정확한가? 출처가 있는가?
- [ ] 저자 정보(작성자명, 프로필)가 표시되는가?
- [ ] **발행 날짜 / 수정 날짜**가 표시되는가?

### 추천 스니펫 노리기

- [ ] "~하는 방법", "~란 무엇인가" 형태의 **H2 섹션**이 있는가?
- [ ] 핵심 내용을 **목록이나 표**로 정리했는가?
- [ ] **FAQ 섹션**을 추가했는가?
- [ ] H2 바로 다음에 **짧은 답변**부터 나오는가?

### 기술 SEO (자동 처리, 확인용)

- [ ] HTTPS 사용 (Vercel 자동) ✅
- [ ] 모바일 친화 (반응형) ✅
- [ ] sitemap.xml 포함 (자동) ✅
- [ ] robots.txt 정상 (자동) ✅
- [ ] Lighthouse 점수 90+ ✅

### 사용자 경험

- [ ] 글 길이가 키워드 의도에 맞는가? (정보형 1,500~3,000자)
- [ ] 이미지가 적절한 위치에 있는가? (긴 문단 분할)
- [ ] 내부 링크 2~5개 포함했는가?
- [ ] 외부 링크 1~2개 (권위 사이트) 포함했는가?
- [ ] 결론 + 다음 액션 안내가 있는가?

## 12. 핵심 요약 — 3줄 정리

1. **구글은 크롤링 → 색인 → 게재** 순으로 작동.\
   내 글이 이 흐름을 타야 노출된다.
2. **E-E-A-T**(경험·전문성·권위·신뢰)를 갖춘 콘텐츠가 순위가 높다.\
   AI 글도 괜찮지만 **내 경험을 반드시 더해야** 한다.
3. **메타 디스크립션과 추천 스니펫**: 클릭률을 높이는 핵심 요소.\
   모든 글에 **155자 이내의 고유한 설명**을 써라.

# 5강. Turso — 블로그 글 저장소 (DB)

> **이 강의에서 배울 것**
> 데이터베이스(DB)가 뭔지, 왜 필요한지, Turso는 어떻게 그걸 무료로 제공하는지, '토큰'이라는 단어가 뭔지 이해합니다.

---

## Turso가 뭐예요?

> 👉 **블로그 글·조회수·댓글을 저장하는 "온라인 엑셀(데이터베이스)" 회사.**

쉽게 말해 **"카페의 매출 장부"**.

| 비유 | 실제 |
|---|---|
| 카페 장부 (오늘 매출, 손님 수) | Turso 데이터베이스 |
| 장부 페이지 (메뉴별 매출, 직원별 출근부) | 테이블 (Table) |
| 한 줄 한 줄의 기록 | 행 (Row) |
| 장부 자물쇠 열쇠 | 토큰 (Token) |

---

## 왜 필요한가요?

블로그에는 글·이미지·조회수·댓글 같은 **계속 변하는 정보**가 있어요.

이걸 어디에 저장할까요?
- ❌ 코드 안에 적기 → 글 추가할 때마다 코드 수정·배포 → 비효율
- ✅ DB에 저장 → 글 추가는 DB만 업데이트 → 코드는 그대로

---

## 핵심 용어 풀이

### 1. DB (데이터베이스, Database)
> "정해진 규칙대로 정리된 데이터 창고."

비유: 도서관의 책 목록 시스템.
- 그냥 책장에 책 쌓아놓기 ❌ → 못 찾음
- 분류별·작가별·연도별 정리 ✅ → 1초 만에 찾음

### 2. 테이블 (Table)
> "DB 안에 있는 '엑셀 시트' 한 장."

예시: 블로그 글 테이블 (`posts`)

| id | title | content | views | created_at |
|---|---|---|---|---|
| 1 | 첫 글 | 안녕하세요... | 230 | 2024-01-01 |
| 2 | 두 번째 글 | 오늘은... | 87 | 2024-01-03 |
| 3 | 세 번째 글 | 또 만났네요 | 12 | 2024-01-05 |

각 칼럼(세로): 어떤 정보를 담을지
각 행(가로): 실제 데이터 한 건

### 3. SQL (Structured Query Language)
> "DB에게 시키는 명령어. 영어와 비슷."

예시:
```sql
SELECT * FROM posts WHERE views > 100;
-- 해석: posts 테이블에서, 조회수가 100 넘는 글을 다 가져와
```

당장 외울 필요는 없어요. Claude가 대신 써줍니다.

### 4. SQLite
> "가장 가볍고 단순한 DB. 한 개 파일로 동작."

Turso는 **SQLite의 클라우드 버전** 입니다.
- 일반 SQLite: 내 컴퓨터에 파일 하나
- Turso: 인터넷 위에 있는 SQLite, 어디서든 접근 가능

### 5. 토큰 (Token / Auth Token)
> "DB에 들어갈 때 보여주는 출입증."

비유: 회사 정문에서 직원증 찍어야 들어가듯, DB에 접속할 때 **'토큰'** 이라는 긴 비밀번호를 제시.

```
eyJhbGciOiJFZERTQSIsInR5cCI6IkpXVCJ9.eyJpYXQiOjE2OTk... (긴 문자열)
```

이걸 코드에 적어 두면, 블로그가 자동으로 DB에 접속해서 글을 가져옵니다.

> ⚠️ **토큰은 절대 GitHub에 올리지 않습니다.** 환경변수에만 적습니다 (4강 참고).

### 6. URL (DB 주소)
> "내 DB가 어디 있는지 알려주는 인터넷 주소."

예: `libsql://my-blog-db-myname.turso.io`

이 URL + 토큰 두 개를 코드에 적으면 = 어떤 DB에 어떤 권한으로 접속할지 결정.

## 작동 흐름

```
방문자가 블로그 글 클릭
        ↓
┌──────────────────┐
│  내 블로그 (Vercel) │
└────────┬─────────┘
         │ "글 데이터 줘"
         │ (URL + 토큰 제시)
         ▼
┌──────────────────┐
│      Turso       │  ← DB 응답
│  (글 데이터 검색)  │
└────────┬─────────┘
         │ "여기 글이야"
         ▼
┌──────────────────┐
│  방문자 화면 표시  │
└──────────────────┘
```

## Turso의 무료 한도

| 항목 | 무료 한도 | 우리가 쓸 양 |
|---|---|---|
| DB 개수 | 500개 | 1개면 충분 |
| 저장 용량 | 9GB | 1년 써도 1GB 못 채움 |
| 월 읽기 횟수 | 10억 | 하루 1만 명 와도 OK |
| 월 쓰기 횟수 | 2,500만 | 충분 |

→ **개인 블로그는 평생 무료** 가능.

---

## 다른 DB와 비교

| DB | 특징 | 무료? |
|---|---|---|
| **Turso** | 가볍고 빠름, 우리가 씀 | ✅ 9GB |
| Supabase | PostgreSQL 기반, 강력 | ✅ 500MB |
| Firebase | 구글, NoSQL | ✅ 1GB |
| MongoDB Atlas | NoSQL 대표 | ✅ 512MB |
| MySQL | 전통적 | 서버 필요 |

→ 입문자에게는 **Turso가 가장 단순**.

## 자주 묻는 질문

**Q. DB 없이는 블로그 못 만드나요?**
- 가능합니다. 글을 `.md` 파일로 코드에 직접 두는 방식 (정적 블로그).
- 단점: 글 추가할 때마다 재배포, 조회수 같은 동적 기능 불가.
- 우리 템플릿은 **DB 기반**, 더 유연.

**Q. SQL 다 외워야 하나요?**
- 아니요. Claude에게 "조회수 높은 글 5개 뽑아줘" 라고 한국어로 시키면 SQL 자동 생성.

**Q. 토큰이 유출되면?**
- 누가 내 DB를 마음대로 읽고 지울 수 있음 → 비상.
- 해결: 즉시 토큰 재발급. 5초.

**Q. Turso 회사가 망하면?**
- DB 데이터 백업 기능 있음 → 안전.
- 그래도 걱정되면 월 1회 백업 추천.

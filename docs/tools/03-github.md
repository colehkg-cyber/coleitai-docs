# 도구 2. GitHub — 코드 창고

> **이 챕터에서 배우는 것**
> - 코드를 왜 "저장소"에 보관하는지
> - Repo / Commit / Push / Pull이 도대체 뭔지 (초등생 비유로)
> - Fork와 Clone의 차이
> - 가입하고 첫 저장소 만들기
> - Personal Access Token이 뭐고 왜 필요한지

---

## 1. GitHub이 뭐예요? — 도서관 비유

### 한 줄 정의

> **GitHub = 코드를 위한 구글 드라이브**

근데 더 똑똑합니다. 단순히 파일을 저장하는 게 아니라:

- 누가 언제 뭘 바꿨는지 **다 기록**합니다
- 잘못 바꿨으면 **과거로 되돌릴 수** 있습니다
- 여러 명이 **동시에** 작업할 수 있습니다
- 다른 사람 코드를 **복사**해서 내 것으로 만들 수 있습니다

### 도서관 비유

GitHub을 도서관에 비유하면:

| 도서관 | GitHub |
|---|---|
| 책 한 권 | **Repository (저장소)** = 프로젝트 1개 |
| 책 안의 챕터 | **파일** (Header.tsx, index.html 같은) |
| 새 판본 발행 | **Commit** = "이 시점의 책 상태를 보관" |
| 도서관에 책 가져다 놓기 | **Push** = 내 컴퓨터 → GitHub으로 올리기 |
| 도서관에서 책 빌리기 | **Pull** = GitHub → 내 컴퓨터로 내려받기 |
| 책을 통째로 복사해서 내 책으로 | **Fork** = 다른 사람 프로젝트를 내 것으로 복사 |

이 단어들 진짜 자주 나오니까 잘 기억해두세요.

## 2. 핵심 용어 — 한 줄씩 풀이

### Repository (Repo, 저장소)

**프로젝트 1개 = Repo 1개**

```
내 블로그 프로젝트
  └─ my-blog 저장소 (Repository)
       ├─ index.html
       ├─ src/
       │   ├─ Header.tsx
       │   └─ Footer.tsx
       ├─ package.json
       └─ ... (수백 개 파일)
```

블로그 코드, 게임 코드, 챗봇 코드... 각 프로젝트마다 Repo 하나.

### Commit (커밋)

**"이 순간의 코드 상태를 저장하자"** 도장 찍기.

```
오늘 작업한 내용
─────────────────
14:30  헤더 색 파란색으로 변경
14:45  ← "헤더 색 변경 완료" 커밋 도장 찍음
15:10  로고 이미지 교체
15:25  ← "로고 교체" 커밋 도장 찍음
```

커밋을 찍어두면 → 나중에 그 시점으로 **되돌릴 수** 있습니다.

> 🎮 게임 세이브 포인트와 같아요. 죽으면 마지막 세이브로 부활.

### Push (푸시)

**내 컴퓨터의 커밋 → GitHub 서버로 올리기**

```
[ 내 컴퓨터 ]                [ GitHub 서버 ]
  커밋 5개 쌓임   ─push→     커밋 5개 도착
```

Push 안 하면 내 컴퓨터에만 있고, 다른 곳에선 못 봅니다.

### Pull (풀)

**GitHub 서버 → 내 컴퓨터로 내려받기**

Push의 반대입니다. 다른 컴퓨터에서 push한 변경사항을 내 컴퓨터로 가져올 때.

### Clone (클론)

**Repo 통째로 내 컴퓨터에 다운로드**

```bash
git clone https://github.com/내아이디/my-blog.git
```

→ `my-blog` 폴더가 내 컴퓨터에 통째로 복사됨. 폴더 + 그 안의 모든 파일 + 커밋 기록까지.

### Fork (포크)

**다른 사람 Repo를 내 GitHub 계정으로 복사**

```
원본 (남의 것)                          내 것 (포크 후)
github.com/anthropic/claude-blog   →   github.com/내아이디/claude-blog
```

Fork = "이 프로젝트 내 것으로 가져와서 마음대로 고치고 싶다" 할 때.

> 🍴 식당에서 음식을 자기 접시로 옮길 때 포크로 찍어오는 것과 비슷한 느낌.

### Branch (브랜치) — 일단 몰라도 됨

협업할 때 쓰는 개념. 우리는 혼자 작업하니까 신경 안 써도 됩니다. 한 줄 설명만:

> 브랜치 = 같은 코드의 다른 버전을 동시에 작업할 때 쓰는 평행 우주. 기본 브랜치 이름은 `main` 또는 `master`.

## 3. GitHub 작동 흐름 — 한눈에 보기

전체 그림:

```
┌─────────────────┐
│   내 컴퓨터       │
│                 │
│  파일 수정 작업   │
│  ↓ git add      │
│  스테이징 (대기실) │
│  ↓ git commit   │
│  커밋 (도장 찍음)  │
│  ↓ git push     │
└────────┬────────┘
         │
         ↓ 인터넷 업로드
┌─────────────────┐
│   GitHub 서버    │
│                 │
│   my-blog repo  │
│   ├─ 커밋 1      │
│   ├─ 커밋 2      │
│   └─ 커밋 3      │
└────────┬────────┘
         │
         ↓ 다른 서비스가 자동 감지
┌─────────────────┐
│     Vercel      │  ← 자동으로 사이트 배포
└─────────────────┘
```

**우리는 git 명령을 외울 필요 없습니다.** Claude Code한테 시키면 됩니다.

```
"방금 작업을 git 커밋하고 push해줘"
→ Claude가 알아서 git add → git commit → git push 실행
```

근데 개념은 알아둬야 무슨 일이 일어나는지 이해합니다.

## 4. 가입하기 (3분)

### Step 1. 회원가입

1. [github.com](https://github.com) 접속
2. 오른쪽 위 **"Sign up"** 클릭
3. 입력값:
   - **이메일**: 본인 이메일 (인증 메일 받을 거)
   - **비밀번호**: 안전한 비밀번호 (15자 이상 추천)
   - **사용자 이름 (username)**: ⚠️ 신중하게 정하세요
4. 사람인지 확인 (퀴즈) 풀기
5. 이메일로 온 인증번호 입력

### Step 2. 사용자 이름 정할 때 주의

이게 **내 GitHub 주소**가 됩니다:

```
github.com/jkim-blog  ← 이게 영구적인 내 주소
github.com/jkim-blog/my-blog  ← 내 저장소 주소
```

**좋은 사용자 이름:**
- 짧고 외우기 쉬움 (15자 이내)
- 영어 소문자 + 숫자 + 하이픈만 사용
- 본인 이름·닉네임 기반

**피해야 할 사용자 이름:**
- `xxx123xxx` 같은 의미 없는 조합
- 본인이 부끄러워할 만한 이름
- 너무 흔한 이름 (이미 사용 중)

> ⚠️ 사용자 이름은 나중에 바꿀 수 있지만, 옛날 주소가 깨지는 등 문제가 생깁니다. **처음에 잘 정하세요.**

### Step 3. 결제 정보? 안 합니다

가입 후 GitHub이 "Pro로 업그레이드 하실래요?" 물어볼 수도 있습니다.

**무료 플랜으로 충분합니다.** 결제 카드 등록 안 해도 됩니다.

| 플랜 | 가격 | 우리한테 필요? |
|---|---|---|
| Free | $0 | ✅ 충분함 |
| Pro | $4/월 | 필요 없음 |
| Team | $4/유저/월 | 회사용 |

개인 블로그·프로젝트는 **평생 무료**입니다.

### Step 4. 이메일 확인

가입 후 GitHub이 이메일로 보낸 **"Verify your email"** 링크 클릭. 안 누르면 일부 기능 제한됩니다.

## 5. 첫 Repository 만들기 (옵션, 연습용)

이건 연습이에요. 실제 우리 블로그는 5강에서 템플릿 복사로 시작합니다.

### Step 1. New repository

1. GitHub 로그인 후 오른쪽 위 **`+` 아이콘** 클릭
2. **"New repository"** 선택

### Step 2. 정보 입력

| 항목 | 입력값 | 설명 |
|---|---|---|
| Repository name | `my-first-repo` | 영어, 띄어쓰기 없이 |
| Description | `연습용 첫 저장소` | 한 줄 설명 (선택) |
| **Public / Private** | **Public** 선택 | 누구나 볼 수 있음 |
| Add a README file | ✅ 체크 | 시작용 README 자동 생성 |
| .gitignore | None | 안 만들어도 됨 |
| license | None | 일단 비워두기 |

### Step 3. Create repository

**"Create repository"** 클릭 → 끝.

→ `github.com/내아이디/my-first-repo` 주소로 접속 가능.

> 🎉 방금 여러분이 만든 게 인터넷 전 세계에 공개된 코드 저장소입니다.

### Public vs Private — 뭘 골라요?

| 항목 | Public (공개) | Private (비공개) |
|---|---|---|
| 누가 볼 수 있나 | 누구나 | 나만 |
| Vercel 무료 배포 | ✅ 가능 | ⚠️ 일부 제한 |
| 검색 노출 | ✅ 됨 | ❌ 안 됨 |
| 비밀 코드 보관 | ❌ 위험 | ✅ 안전 |

**블로그 코드는 Public이 맞습니다.** 어차피 누가 봐도 상관없는 코드고, Vercel 배포가 무료입니다. 비밀번호·키 같은 건 `.env` 파일로 분리해서 보관 (8강에서 다룸).

## 6. Personal Access Token (PAT) — 비밀번호의 신분증

### 이게 뭐예요?

옛날엔 GitHub에 push할 때 **GitHub 비밀번호**를 입력했습니다. 지금은 비밀번호 대신 **"Personal Access Token"** (PAT, 개인 접근 토큰)을 씁니다.

### 왜 바뀌었어요?

비밀번호는 강력하고 영구적입니다. 새면 큰일 납니다.

PAT는:
- **권한 제한 가능** (예: "이 토큰은 push만 가능, 삭제는 안 됨")
- **유효기간 설정** (예: "30일 후 만료")
- **여러 개 발급** (서비스마다 다른 토큰)

새도 한 토큰만 폐기하면 끝. 비밀번호 자체는 안전.

### PAT 발급 (필요할 때만)

지금은 안 만들어도 됩니다. 7강(blog 커스터마이징)에서 push할 때 인증 오류 나면 그때 발급:

1. GitHub 우상단 본인 프로필 → **Settings**
2. 왼쪽 맨 아래 **Developer settings**
3. **Personal access tokens** → **Tokens (classic)**
4. **Generate new token (classic)** 클릭
5. 설정:
   - **Note**: `claude-code-blog` (메모용)
   - **Expiration**: `90 days` (또는 No expiration)
   - **Select scopes**: ✅ `repo` 체크 (이것만 있으면 됨)
6. **Generate token** 클릭
7. `ghp_xxxxxxx...` 형태의 토큰이 한 번만 표시됨 → **즉시 메모장에 복사**

:::danger 토큰은 딱 한 번만 보여줍니다
페이지를 떠나면 다시 못 봅니다. 못 복사했으면 새로 발급해야 합니다.
:::

:::danger 토큰은 비밀번호 그 자체
이게 새면 누가 내 코드를 마음대로 수정·삭제할 수 있습니다. 카톡·이메일·블로그에 절대 올리지 마세요.
:::

## 7. GitHub과 다른 도구의 연결 관계

우리 블로그 시스템에서 GitHub의 위치:

```
┌──────────────┐
│   내 컴퓨터    │ ← Claude Code가 여기서 코드 수정
│  (VS Code)   │
└──────┬───────┘
       │ git push (변경사항 업로드)
       ↓
┌──────────────┐
│    GitHub    │ ← 코드 저장 (Repo)
└──────┬───────┘
       │ 자동 감지 (Webhook)
       ↓
┌──────────────┐
│    Vercel    │ ← 변경 감지하면 자동으로 사이트 빌드 + 배포
└──────┬───────┘
       │
       ↓
   🌐 내 블로그가 업데이트됨
```

**GitHub은 모든 것의 중심**입니다.
- 코드의 **유일한 진실의 원천** (Single Source of Truth)
- Vercel은 GitHub만 봅니다
- 내가 글을 쓰는 Decap CMS도 GitHub에 저장합니다

## 8. 자주 묻는 질문

**Q1. GitHub 사용자 이름을 잘못 정했어요. 바꿀 수 있나요?**
가능합니다 (Settings → Account → Change username). 하지만 옛 주소가 깨집니다. 외부에서 옛 주소를 링크한 곳이 다 깨져요. 가능하면 처음에 잘 정하세요.

**Q2. 비밀번호를 잊어버렸어요.**
GitHub 로그인 화면에서 "Forgot password?" → 이메일로 재설정 링크.

**Q3. 2단계 인증(2FA)을 해야 하나요?**
2023년부터 GitHub은 모든 사용자에게 2FA를 의무화하는 추세입니다. 가입 시 또는 1년 이내에 설정 요청이 옵니다. 휴대폰 SMS보다 **Authenticator 앱**(Google Authenticator, 1Password 등)을 추천.

**Q4. 한국어 사용 가능한가요?**
GitHub UI는 영어가 기본이지만, 한국어 설정 가능합니다 (Settings → Appearance → Language). 다만 일부 기능은 영어로만 표시됩니다.

**Q5. GitHub Desktop이 뭐예요?**
GitHub이 만든 **데스크탑 앱**입니다. 터미널 명령 대신 마우스 클릭으로 git을 쓸 수 있어요. 하지만 우리는 Claude Code가 git을 대신 해주니까 안 써도 됩니다.

**Q6. private repo를 무료로 쓸 수 있나요?**
네, 가능합니다. 2020년부터 private repo도 무료입니다. 다만 Vercel 무료 플랜은 public repo가 더 편합니다.
